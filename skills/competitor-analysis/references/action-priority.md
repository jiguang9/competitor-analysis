# 行动优先级框架：跟 / 缓 / 不跟

每条重要发现最终必须落到可执行的判断，而不是停留在"竞品做了什么"的描述层面。

## 判断维度

对每一个值得关注的竞品动作或洞察，从三个维度评估：

1. **影响程度**：是否直接影响我方用户、核心渠道或收入相关的关键指标？还是与我方当前定位、目标用户无关的边缘动作？
2. **证据确定性**：支撑这个判断的数据是否明确（verified fact），还是更多依赖推测（inference）？证据链越弱，越应该谨慎行动。
3. **执行成本与可逆性**：响应这个动作需要多大投入？如果判断错了，调整回来的代价高不高？

## 三档判断

| 判断 | 条件 | 处理方式 |
|---|---|---|
| 跟（优先处理） | 高影响 + 高确定性 + 低执行成本（通常 1–3 天内可完成） | 看到就做，写入"立即行动" |
| 缓（记录观察） | 竞品有动作，但影响是否持续尚不确定，或需要更多数据验证 | 记录进待观察清单，下次报告再评估，不要仓促反应 |
| 不跟（暂缓处理） | 竞品在做某件事，但和我方目标用户、当前定位或本阶段业务目标无关 | 明确写出"暂缓处理"及理由，避免团队因为竞品热闹而盲目跟随 |

**提醒**：每看到竞品动作就焦虑反应，最终会被竞品牵着走、偏离自己的产品和用户判断。"不跟"和"跟"一样是一个需要写出理由的主动判断，不是消极忽略。

## 下一步最小验证动作

对于标记"跟"或"缓"的项目，给出具体的下一步验证动作，而不是笼统的"持续关注"：

- 具体到"验证什么"：例如"确认竞品新定价是否已经在全平台生效，还是仅限定活动"。
- 具体到"用什么方式验证"：例如"下次报告重新访问价格页确认""向 3 个目标客户询问对该功能的反应"。
- 具体到"什么时候看结果"：给出一个大致的时间窗口（例如"下次报告""两周内"）。

## 衡量行动是否有效

给出的行动建议应附带一个简单的衡量方式，帮助用户判断这个行动之后要不要继续投入：

- 指标类型：例如内容互动率变化、转化率变化、客户反馈变化、竞品后续动作变化。
- 观察窗口：多久后回看一次（例如"两周后""下次报告"）。
- 不需要复杂的 KPI 体系，重点是"如何判断这个行动生效"这句话本身能不能被回答，回答不了说明行动建议本身不够具体。

## So What 检查清单

在最终定稿一条重要发现之前，检查它是否回答了：

1. 对我方意味着什么？
2. 是否需要行动？
3. 为什么是现在（而不是下个月）？
4. 下一步最小验证动作是什么？
5. 如何判断这个行动有效？

五个问题都答不出来的发现，不应该出现在报告的"行动建议"部分，可以降级放入"待观察"或"背景信息"。
