# 竞品集合与分类

在深入分析任何竞品之前，先确定"到底该分析谁"。把搜索和分析精力花在错误的对象上，是竞品情报最常见的浪费。

## 六种关系类型

面对用户提到的名字，或 Agent 自动发现的候选名单，先把每一个归入以下类型之一：

| 类型 | 定义 | 分析方式 |
|---|---|---|
| 直接竞品 | 相同用户、相同需求、相近解决方案 | 进入五维度深度分析 |
| 替代方案 | 不同产品形态，但解决相同问题（例如用 Excel 替代 SaaS 工具） | 至少覆盖 D1、D3、D5，用来理解用户的真实备选项 |
| 手工作业或不行动 | 表格、人工流程、自建方案、继续维持现状 | 不做五维度分析，但要记录"为什么用户会选择不作为" |
| 相邻威胁 | 当前不是直接竞品，但可能通过产品扩展进入 | 记录扩展信号（融资、招聘、新功能预告），不做深度分析 |
| 规则制定者 | 平台方、监管方、行业标准组织，影响市场规则但不作为竞品 | 仅记录影响，不纳入比较表 |
| 生态伙伴 | 供应商、渠道方、可能的合作对象 | 不纳入竞品分析 |

## 为什么要先分类

- 替代方案和手工作业往往是最大的"真实对手"，尤其是在 To B 场景下，很多客户的真实备选项是"继续用 Excel"而不是任何一个 SaaS 产品。跳过这一类会让分析看起来完整但结论偏离现实。
- 相邻威胁如果被当成直接竞品来做五维度深度分析，会浪费大量搜索预算在还没有发生的竞争上。
- 规则制定者和生态伙伴混入比较表，会让统一维度比较表失去意义（它们本来就不适用相同的比较维度）。

## 用户确认流程

1. 列出候选名单，标注每个名字目前判断属于哪一类型，并附一句话理由。
2. 明确指出：如果是 Agent 自动发现的候选（用户没有主动提供），必须先展示分类结果，再询问用户"是否以此为准进入深挖"。
3. 用户可以调整分类、增删候选。不要在未确认前就为候选启动大量搜索。
4. 如果用户直接给出了竞品名单（例如"帮我分析 A、B、C"），仍然做分类展示，但可以视为已经默认确认，除非用户的名单明显包含替代方案或生态伙伴（此时提示一句，请用户确认是否按相同深度分析）。

## 假竞品过滤

以下情况即使用户提到了名字，也不应该直接进入五维度深度分析，需要先向用户澄清：

- 名字对应的是一个已经停止运营或长期未更新的产品（需要先核实经营状态，不能凭印象判断）。
- 名字对应的是一个内部工具、白牌产品或未公开定价和用户群体的实体，缺乏可核实的公开信息。
- 名字实际上是一个大公司的子品牌或功能模块，而不是独立产品——需要明确分析范围是母公司还是该功能本身。
- 用户列出的"竞品"数量超过 3 个（Quick 模式默认建议）或分析目的与部分候选无关——建议用户按优先级收窄。

## 竞品集合会变化

竞品集合不是一次性决定。在竞品报告（模式④）中，如果本期发现新的候选竞品或某个竞品明显退出竞争（例如产品下线、被收购），需要在报告中标注集合变化，并说明是否需要用户重新确认集合，而不是默默地更新范围。
